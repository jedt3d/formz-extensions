# Domain documentation

Use the single-context layout: root GLOSSARY.md and docs/adr/.

Before domain or architectural work, read GLOSSARY.md if present and relevant ADRs under docs/adr/. If absent, proceed; this setup does not create speculative glossary entries or architectural decisions.

Use the glossary's terms when available. Until a term is defined there, use the existing Array vocabulary: Sources, Targets, layout, pitch, clear gap, repetition, preview, gate, accepted baseline, and LINE_READY. Keep native topology, NURBS control points, sampled points, and display facets distinct.

If a proposed change conflicts with an existing ADR, identify that conflict before implementation.
